# SweetHome

Vue 3, Spring Boot 3, MariaDB 기반 가정용 식물 관리·가계부 프로젝트입니다.

## 1. Overview

SweetHome은 집에서 직접 사용할 생활 관리 시스템의 필요성에서 출발한 프로젝트입니다. 여러 화분을 기르다 보니 식물마다 물을 주는 시기와 관리 방법이 달라, 기억에 의존하는 관리에 한계가 있었습니다. 이를 데이터로 관리하는 방식으로 디지털 전환하고자 식물별 정보와 물주기 주기·이력을 기록하는 기능부터 개발했습니다.

이후 아내가 사용할 가계부 기능을 추가해 수입·지출 내역과 월별 흐름을 함께 확인할 수 있도록 확장했습니다. Vue 기반 화면과 Spring Boot REST API, MariaDB를 연결해 가정에서 발생하는 관리 정보를 하나의 대시보드에 모았습니다.

가계부 내역의 등록·수정·삭제나 화분의 물주기 기록 갱신이 발생했을 때 관련 정보를 전달하기 위해 Telegram 봇을 연동했습니다. 현재는 메시지 전송 서비스와 테스트 API까지 구현했으며, 가계부·물주기 변경 이벤트에 알림을 연결하는 작업은 추가 개발할 예정입니다.

### 개발 범위 및 기여도

**가정 내 필요를 직접 발굴하고, 기획·화면 구성·DB 설계·프론트엔드·백엔드 개발을 단독으로 담당한 개인 프로젝트입니다.** 식물 관리로 시작해 아내의 가계부 사용 요구를 반영하고, 알림과 IoT 제어로 확장할 기능을 단계적으로 정의했습니다.

| 단계 | 담당 내용 |
|---|---|
| 기획·요구사항 정의 | 여러 화분의 관리 정보를 데이터로 기록할 필요를 발견하고, 가족이 사용할 가계부 요구를 기능으로 구체화 |
| 화면·데이터 설계 | 식물 목록·상세·물주기 이력, 가계부 달력, 홈 대시보드와 MariaDB 데이터 모델 설계 |
| 프론트엔드 개발 | Vue 기반 화면, CRUD API 연결, 이미지 업로드, 월·주·일 조회와 수입·지출 집계 구현 |
| 백엔드 개발 | Spring Boot REST API, 입력 검증, JPA 저장 처리, 물주기 트랜잭션 구현 |
| 외부 서비스 연동 | Telegram 메시지 전송 서비스와 테스트 API 구현; 변경 이벤트 알림 및 Home Assistant 연동은 후속 개발 범위로 정의 |
| 빌드·문서화 | 프론트·백엔드 빌드 확인, 실행 환경·API 계약·현재 제약 정리 |

### 핵심 문제 해결

| 문제 | 설계·구현 결정 | 의도 |
|---|---|---|
| 화분마다 물주기 시기가 달라 기억에 의존하기 어려움 | 식물별 주기·마지막 물주기·이력을 저장하고 예정 시점을 화면에 표시 | 관리 상태를 데이터로 확인 |
| 가족이 사용할 가계부 기능이 필요해짐 | 거래 CRUD와 월·주·일 화면, 대시보드 집계를 추가 | 생활 관리 기능을 실제 사용자 요구에 맞춰 확장 |
| 물주기 이력과 최근 시각의 일관성이 필요함 | 이력 저장과 식물 갱신을 하나의 트랜잭션으로 처리 | 일부 처리만 반영되는 상황 방지 |
| 화면에 접속하지 않아도 변경 정보를 전달하고 싶음 | Telegram 전송 기반을 구현하고 가계부·물주기 이벤트 연결을 후속 단계로 계획 | 생활 이벤트 알림으로 확장할 기반 마련 |

### 향후 확장 계획

Home Assistant와 연동하여 집 안의 IoT 기기를 제어하는 페이지를 개발할 계획입니다. 식물 관리와 가계부로 시작한 시스템을 가정 내 기기 제어까지 확장하는 것을 목표로 합니다.

### 주요 기능

| 영역 | 구현 내용 |
|---|---|
| 홈 대시보드 | 당월 수입·지출·잔액, 최근 거래 5건, 식물별 물주기 예정 표시 |
| 식물 관리 | 등록·조회·부분 수정·삭제, 구매일·물주기 주기 관리 |
| 물주기 이력 | 물주기 시각과 요청 출처 저장, 식물의 최근 물주기 시각 갱신 |
| 이미지 | multipart 업로드, 로컬 파일 저장, 상대 URL로 조회 |
| 가계부 | 날짜 범위 조회, 수입·지출 등록·수정·삭제, 월·주·일 단위 UI |
| API 문서 | springdoc OpenAPI / Swagger UI |
| Telegram | 테스트 API에서 고정 메시지를 지정 채팅으로 전송 |

### 구현 포인트

- **프론트·백엔드 분리:** Vue Router 기반 SPA와 Spring Boot REST API를 각각 빌드합니다.
- **영속 데이터와 화면 집계 연결:** 가계부 목록을 조회한 뒤 프론트에서 수입·지출·잔액을 계산하고, 식물 데이터로 물주기 일정을 표시합니다.
- **트랜잭션 단위 처리:** 물주기 이력 추가와 식물의 마지막 물주기 시각 갱신을 하나의 서비스 트랜잭션에서 처리합니다.
- **파일과 데이터 분리:** 이미지는 파일시스템에 저장하고 DB에는 접근 URL을 보관합니다.
- **외부 서비스 확장:** Spring `RestClient`로 Telegram `sendMessage`를 호출하는 서비스를 구성했습니다.


## 공개용 소스

최신 기능을 분리한 공개용 스냅샷입니다. 운영 자격 증명, 개인 사진, 실제 식물 샘플 데이터 및 기존 Git 이력은 포함하지 않습니다.

## 실행

필요 환경: JDK 17, Node.js 20, MariaDB.

1. 빈 개발 DB에서 `doc/db_script.sql`을 실행합니다. 초기화 SQL은 기존 식물·물주기 테이블을 삭제하므로 운영 DB에서 실행하지 마세요.
2. `.env.example`을 참고해 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`를 셸 환경변수로 설정합니다. Spring Boot는 `.env` 파일을 자동으로 읽지 않습니다.
3. 백엔드: `cd backend && sh ./gradlew bootRun`
4. 별도 터미널에서 프론트: `cd frontend && npm ci && npm run dev`
5. `http://localhost:5173`에 접속합니다. 백엔드는 기본 `127.0.0.1:9090`에서 실행합니다.

프론트 빌드: `cd frontend && npm run build`
백엔드 패키징: `cd backend && sh ./gradlew compileTestJava bootJar --no-daemon`
DB 컨텍스트 테스트는 실행 가능한 테스트 DB와 환경변수가 필요합니다.

## API와 보안 범위

- `/api/plants`: 식물 CRUD, 이미지 업로드, 물주기·이력
- `/api/account`: 날짜 범위 조회, 거래 CRUD
- `/swagger-ui/index.html`: API 문서
- 텔레그램 테스트는 기본 비활성화입니다. `TELEGRAM_ENABLED=true`와 토큰·채팅 ID를 설정하면 `POST /api/telegram/test`로 실제 메시지를 보냅니다.

개인용 로컬 실행을 전제로 하며 API 인증·사용자별 권한 분리는 아직 구현하지 않았습니다. 인터넷 배포 전 인증 및 접근 제어가 필요합니다. CORS는 인증 수단이 아닙니다. 이미지 업로드에는 파일 형식 검증과 추가 보호가 필요합니다.

실제 토큰과 비밀번호는 환경변수나 외부 비밀 저장소로 관리하세요. 업로드 사진과 개인 설정 파일은 Git 추적에서 제외합니다.

## 검증

공개용 소스의 프론트 프로덕션 빌드와 백엔드 compileTestJava/bootJar가 성공했습니다. DB 통합 테스트 및 텔레그램 실제 전송은 실행하지 않았습니다. npm audit fix 적용 후 프론트 개발 도구 의존성에 취약점 2건(중간 1, 높음 1)이 남아 있습니다. Vite 주요 버전 업그레이드와 호환성 검증은 후속 과제입니다. 개발 서버를 인터넷에 노출하지 마세요.
